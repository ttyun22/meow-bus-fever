# 🚌 巴士大疏通

一款巴士交通解谜 H5 休闲游戏：停车场堵成一锅粥，玩家点击巴士让它们
沿车头方向驶出、接走匹配颜色的乘客、在有限的接客位周转，直到送走所有乘客。

纯前端实现（HTML + CSS + JavaScript ES Modules），**无构建步骤、无后端、
无外部资源依赖**，桌面浏览器与手机竖屏均可直接游玩。

> 玩法类型借鉴「巴士疏通 / 停车场拥堵」品类，游戏名称、关卡、美术与
> 代码全部原创。

---

## 一、启动方式

任选其一（在项目根目录执行）：

```bash
# 方式 1：Python（macOS / Linux 自带）
python3 -m http.server 8080

# 方式 2：Node
npx --yes serve -l 8080
```

然后浏览器打开 <http://localhost:8080>。

> ES Modules 不能直接用 `file://` 协议打开，必须经本地 HTTP 服务器。

关卡逻辑验证（BFS 求解器，Node 直接运行）：

```bash
node src/game/solver.js
```

## 三、核心规则

### 巴士与停车场
- 停车场是 `cols × rows` 网格；每辆巴士占据若干格（长度 2~3）。
- 巴士**只能沿车头朝向直线移动**，点击即尝试驶出停车场。
- 驶出条件：车头到棋盘边缘的整条路径无其他巴士（被挡时播放
  摇头动画 + 挡路车闪烁 + toast 文案，不执行移动）。
- 驶出后进入接客位；**接客位有空位才能驶出**（满时点击提示）。

### 乘客颜色匹配
- 场外候车队列**有序**：只有队首乘客可以上车。
- 乘客只上**颜色匹配且未满座**的接客位巴士，上车自动结算。
- 巴士**满载**、或队列中已无同色乘客（该色任务完成）时自动**发车离场**，
  释放接客位。

### 胜利 / 失败
- **胜利**：所有乘客上车且接客位清空（稳定态自然成立）。
- **失败（死锁）**：局面稳定（无任何自动结算）且玩家没有任何合法操作
  （接客位全满或所有巴士被挡），乘客仍未运完。
  失败弹出覆盖层，点「重试本关」重置当前关，**不刷新网页**。

### 状态一致性建模
- 巴士是否占棋盘格子只由 `status === 'board'` 决定（占用表由全部
  board 巴士**派生**，不单独存储，天然不会错位）；
- 巴士与接客位的占用通过 `slots[i].busId` 与 `bus.slotIndex` 双向同步，
  且只有 `moveBus / departReady` 两个入口会同时改写两侧。
- 防异常：`validateMove` 前置校验；`checkWin / checkLose` 只在
  稳定态调用且只允许翻转一次状态。

### 并行操作模型（取代早期全局输入锁）
- 逻辑先行：点击巴士时 `moveBus` 在**同一个同步栈**内完成校验、
  快照入栈与接客位原子预留，`moveCount` 同步 +1——提交顺序 = 点击顺序，
  不存在竞态；同一辆巴士提交后 `status` 立即变为 `loading`，重复点击被忽略。
- 一辆巴士上客/动画期间，可直接点击另一辆合法巴士并行操作；
  接客位满时点击会提示「接客位已满」且不消耗操作次数。
- 动画层只锁冲突资源而非全局：`activeExits` 归零前不做棋盘全量重渲染；
  自动上车/发车结算循环全局单例（`settleRunning`/`settlePending` 合并请求）；
  `pendingArrivals` 保证乘客只飞向「视觉上已到位」的巴士。
- 撤回与并行兼容：快照可能取于上一操作的自动结算尚未回放的瞬间，
  撤回后同步重放 `settleAll` 保证恢复到稳定闭环状态；
  动画/结算进行中撤回按钮自动禁用，不会恢复到半完成动画状态。

## 四、状态模型与核心函数

`state`（见 `src/game/logic.js` 顶部注释）：

| 字段 | 含义 |
| --- | --- |
| `levelId / grid` | 关卡编号、网格尺寸 |
| `buses` | 每辆巴士：位置(x,y)、长度、朝向、颜色、容量、`status`（board/loading/departed）、`slotIndex`、`passengers` |
| `slots` | 接客位数组：`{index, busId \| null}` |
| `queue` | 候车乘客（index 0 为队首） |
| `moveCount` | 玩家操作次数（点击驶出次数） |
| `status` | `playing / won / lost` |

导出的规则函数（与任务要求一一对应）：

| 函数 | 职责 |
| --- | --- |
| `initializeLevel(level)` | 从关卡配置构建全新 state |
| `validateMove(state, busId)` | 校验驶出合法性（blocked / no-slot 等） |
| `moveBus(state, busId)` | 执行驶出（棋盘→接客位），返回动画事件 |
| `boardPassengers(state)` | 结算自动上车（返回 board 事件） |
| `departReady(state)` | 结算自动发车并释放接客位（返回 depart 事件） |
| `checkWin / checkLose` | 胜利 / 死锁判定（稳定态调用） |
| `restartLevel(level)` | 重置当前关（= 重新 initializeLevel） |
| `loadNextLevel` | 进入下一关（controller 实现：换配置重新初始化） |

UI 侧按逻辑返回的**事件序列**播放动画（驶出滑行、乘客飞入、发车离场），
每个事件播完立即重渲染校准，任意时刻 DOM 与 state 一致。

## 五、关卡设计与批量验证（50 关）

当前共 **50 关**。第 1–5 关保留最初的教学设计；第 6–50 关按车辆规模递进：

| 关卡区间 | 车辆数 | 接客位 | 设计重点 |
| --- | ---: | ---: | --- |
| 1–5 | 2–6 | 1–2 | 核心循环、阻挡、唯一接客位、依赖链 |
| 6–10 | 5–7 | 2 | 多方向 / 长短车 / 基础阻挡链，少量提前等待 |
| 11–20 | 7–10 | 2 | 颜色阶段与阻挡链交叉，安排离场顺序 |
| 21–30 | 10–12 | 2–3 | 接客位容量开始成为硬约束 |
| 31–40 | 12–15 | 3 | 高密度车阵，少一个接客位即无解 |
| 41–50 | 15–18 | 3 | 终盘高密度：7–11 层依赖链 + 大量阻挡关系 |

第 1–5 关（原始教学关，未改动）：

| 关 | 名称 | 难度 | 教学目标 / 机制 | par（最短步数） |
| --- | --- | --- | --- | --- |
| 1 | 初来乍到 | 1 | 完整核心循环：点击驶出 → 颜色匹配 → 满载发车 | 2 |
| 2 | 谁挡了谁 | 2 | 阻挡关系与移动顺序；乱占接客位会死锁 | 3 |
| 3 | 一位难求 | 2 | 唯一接客位：必须严格按队首颜色放车 | 3 |
| 4 | 层层开路 | 3 | 长度/朝向混合，三层依赖链（蓝→绿→红） | 4 |
| 5 | 终极疏通 | 4 | 路径链 + 双向竖直 + 颜色错位 + 死锁陷阱综合 | 6 |

每关在 `levels.js` 中记录：`difficulty`（难度标签）、`intent`（设计意图）、
`hint`（玩家提示）、`solution.moves`（参考解法）与 `solution.par`。

完整的逐关数据（车辆数、接客位、阻挡边数/链深、最短步数、BFS 状态数、
求解耗时、少一个接客位是否仍可解）见根目录 [`LEVEL_STATS.md`](LEVEL_STATS.md)，
可用 `node src/game/solver.js --write-stats` 重新生成。

**注册与加载**：`src/game/levelRegistry.js` 是关卡数据的唯一访问入口
（`getLevelCount / getLevelByIndex / getLevelById / listLevelSummaries`）。
UI、求解器、开始页文案都经注册表取数，不存在散落的硬编码关卡数。
加载缺失或不合法的关卡时，游戏显示可读的「关卡加载失败」覆盖层
（含具体原因 + 回到首页），不会白屏。

**统一验证流程**：`node src/game/solver.js`（或 `npm run verify`）对注册表
中的每一关依次执行：

1. 配置校验（`validateLevelConfig`）：字段格式、网格/接客位范围、
   巴士越界与重叠、队列颜色与车辆容量一致性、参考解法引用合法性，
   并告警当前规则不支持的未知字段（防止虚假配置）；
2. BFS 可解性搜索（与游戏运行时完全相同的 `logic.js` 规则），
   记录去重后的状态数与求解耗时；
3. 参考解法真实回放验证；
4. `par` 与 BFS 最短解一致性比对；
5. 可达死锁状态检测（失败陷阱是否真实存在）；
6. 容量对照：接客位 > 1 时，把接客位减 1 再跑一次 BFS。只有对照搜索
   完整跑完且确实无解时，才标记为「少一位无解」；搜索超限明确标注
   「未验证」，不会把「没搜到」当成「无解」。

50 关全部通过配置校验、BFS 与参考解法回放；第 6–50 关的 `par` 均等于
车辆数（每辆车都必须驶出一次），第 9 关起均存在可达死锁陷阱。

新增一关 = 在 `levels.js` 追加一份配置 + 重跑验证，无需改动其他文件。

**分阶段教学**：`src/ui/tutorial.js`（配置与关卡数据分离）——
第 1 关教基本上车与颜色匹配，第 2 关教路径阻挡，第 3 关教接客位容量
与满载发车，第 4–5 关为顺序与死锁风险的简短提示。教学在首次遇到时
触发、玩家完成指定操作后自动结束、通关即视为掌握并持久化
（localStorage），失败/重开不再重复弹出；全程不阻塞合法操作。

**驶出路径预览**（桌面 hover）：只读高亮「车头到棋盘边缘」的路径格，
畅通为绿、首个阻挡格为红；不修改任何游戏状态。触屏沿用点击后的
摇头 + 挡路车闪烁反馈。

**事件音效**：`src/ui/sound.js`（Web Audio 程序化合成，无外部素材），
覆盖按钮点击 / 巴士驶出 / 乘客上车 / 非法操作 / 撤回 /
失败 / 通关 7 类事件（发车离场音效已移除——发车由动画表达即可）；统一静音开关（HUD 🔊 按钮，localStorage 持久化）、
同名 90ms 去重防叠加、播放失败静默、首次用户手势解锁自动播放策略。

**点击音效试听选择器**：`sound-lab.html`（独立工具页）提供 6 种
差异明显的点击候选（A 清脆轻点 / B 柔和木质 / C 软弹反馈 /
D 电子确认 / E 轻快双音 / F 柔和气泡），支持互斥试听（防叠加）、
音量与静音控制、「选用此音效」本地保存（`bus-click-sound-v1`）。
**当前选择尚未接入主游戏**，待确认后统一替换。

## 七、已知问题与限制

- 后台/被遮挡的标签页中，浏览器会对定时器节流，动画与结算明显变慢
  （前台游玩无影响；`?fast=1` 可跳过动画等待）。
- 动画采用 CSS transition + 固定时长（约 0.3~0.45s），极低性能设备上
  可能掉帧，但不影响规则正确性。
- 巴士棋盘内位置固定（只有驶出一种移动），是刻意的规则简化；
  未来可加入「格内挪动」提升深度。
- 主游戏点击音效仍是初版占位音（`SFX.click`），待试听选择器确认
  最终方案后统一替换；无背景音乐（刻意保持轻量）。
- 无进度存档（刷新后回到第 1 关）。
